# Decision Brief — 의사결정 브리핑 문서 작성 규칙

경영진·파트너 기관·이해관계자를 대상으로 **하나의 결정을 이끌어내는** 문서를 만든다. 체크리스트 나열이 아니라 "읽는 사람이 결정할 수 있는 순서"로 쓰고, **글만 이어지는 화면이 없도록** 섹션마다 시각 요소를 배치한다.

## 0. 시작 전 반드시 확인

설득 방향과 대상이 문서 구조를 바꾸므로, 둘 중 하나라도 불명확하면 먼저 묻는다.
- **원하는 결론**: 무엇에 합의/승인/보류/종료하도록 설득하는가
- **대상과 형식**: 실무진 / 경영진·책임자 / 온라인, 참석자 구성

명확하면 묻지 않고 바로 시작한다.

## 1. 산출물

- **단일 HTML 파일**로 작성. 파일명: `YYMMDD_<주제>_<문서유형>_v<n>.html`
- 수정 요청이 오면 새 버전 파일로 (v2, v3…).

## 2. 구조 (고정 순서) — 각 섹션의 기본 시각 요소 포함

| # | 섹션 | 목적 | 기본 시각 요소 |
|---|------|------|-------------|
| Cover | 제목·부제·회의/대상/제안/작성 메타 | 무엇을 제안하는 문서인지 | 없음 (타이포그래피로 충분) |
| Strip | 핵심 수치 4개 (충족→부족→결정적 수치) | 숫자로 상황 고정 | 수치 타일 4개 |
| 01 요약 | 2~3문장 결론 + 사실/검토/제안 3패널 | 이 페이지만 읽어도 결정 가능 | **요약 그림 1개** (문제→원인→제안 흐름도, 또는 현황 vs 요건 갭 다이어그램) |
| 02 목표와 요건 | 목표 vs 달성 요건 vs 현황 표 | 판단 기준을 합의된 목표로 고정 | 표 + 현황 열은 태그(충족/미충족) |
| 03 정량 검토 | 직접 계산한 수치 | 의견이 아니라 계산 | **차트 2~3개** (곡선/기준선, 누적막대, 규모 비교 막대) |
| 04 다관점 검토 | 4개 전문 관점 + 각 "판정" | 서로 다른 언어로 같은 결론 | 2×2 패널 그리드 + **수렴 다이어그램** (4개 화살표가 한 결론으로) |
| 05 검토한 대안 | 대안 / 결과 / 잔존 제약 | 안 해본 것이 아니다 | 표, 또는 대안별 "해소 정도" 히트바 |
| 06 추진 방향별 영향 | 진행 시 vs 보류 시 | 상대 입장의 손익 | 2패널 비교 + **일정·비용 타임라인 그림** (두 경로를 위아래로) |
| 07 제안 | 권고 1안 + 2안 + 비권고 3안 | 선택지를 주되 권고는 하나 | 3패널, 권고안은 dark 패널 |
| 08 예상 질의와 답변 | 6~8개 | 질문에 사실로 답함 | Q/A 리스트 |
| 09 합의 요청 사항 | 필수/권장 체크리스트 + 후속 일정 + 맺음말 | 당일 받아올 것 | 표 + **D+n 타임라인** |
| 10 표현 지침 | 권장 / 지양 | 발언 톤 통제 | 2패널 |
| Foot | 근거 및 가정 | 추적 가능성 | 없음 |

주제에 따라 섹션을 빼거나 합칠 수 있으나 **01·03·04·07·09는 생략하지 않는다.**

## 3. 시각화 원칙 — 가독성 확보

**규칙: 화면 한 폭(약 900px) 안에 글만 있는 구간이 없어야 한다.** 섹션마다 표·차트·다이어그램·수치 타일·패널 중 최소 하나. 문서 전체에 **차트·다이어그램 최소 5개**.

| 내용 | 형식 |
|------|------|
| 수치 하나가 결정적 | 수치 타일 — 큰 세리프 숫자 + 짧은 라벨 |
| 표본수·신뢰구간·비용 등 연속변수 관계 | 선 차트 + 기준선(목표치) + 현위치 마커 |
| 한 전체를 나눈 구성 | 누적 막대 1줄 (도넛 금지) |
| 규모 비교 (우리 vs 목표 vs 벤치마크) | 가로 막대, 같은 축 |
| 목표 vs 현황 다수 항목 | 표 + 태그, 또는 갭 다이어그램 |
| 흐름·인과·의사결정 | 박스-화살표 다이어그램 (SVG) |
| 일정·경로 비교 | 가로 타임라인 2줄 |
| 여러 관점이 한 결론으로 | 수렴 다이어그램 (N 노드 → 1 결론) |
| 옵션 비교 | 나란히 패널, 권고안 강조 |

제작 규칙:
- 모두 **인라인 SVG**로 직접 그린다. 외부 차트 라이브러리·이미지 파일·이모지 금지. viewBox 760폭 기준.
- 차트 좌표는 Python으로 계산해 넣는다. 추정해서 그리지 않는다.
- 각 그림에 상단 소제목(`Fig n · 제목`)과 하단 **"해석:"** 캡션 2~3문장. 그림만 보고도 결론이 읽히게 라벨·마커·기준선을 그림 안에 넣는다.
- 의미 색 고정: 부족/음영 red, 충족/보존 green, 주의/미확정 amber, 제안/강조 blue, 기준·벤치마크 ink.
- 장식용 그림 금지. "이 그림을 빼면 어떤 문장이 길어지나?"에 답할 수 없으면 뺀다.
- 긴 단락은 3문장 이내, 4항목 이상 나열은 표로.

## 4. 데이터 근거 원칙

- 수치는 **반드시 직접 계산** (Bash/Python). 신뢰구간(Wilson), 표본수, 검정력, 비율 — 추정치를 문장으로 쓰지 않는다.
- 외부 기준(WHO, 식약처, FDA, 학회 가이드라인, 벤치마크 논문)은 웹 검색으로 **출처를 확인한 뒤** 인용하고 Foot에 링크·서지를 남긴다. 확인 못 한 기준은 수치로 쓰지 않고 "1차 자료 미확인"으로 사용자에게 알린다.
- 내부 목표치와 법정 기준을 구분해 표기한다.
- 설명용 가정(분할 비율 등)은 캡션과 Foot에 "설명용 예시"로 명시한다.

## 5. 다관점 검토 (04) 작성법

주제에 맞는 4개 관점을 고른다. 의료 AI 기본 세트: **임상의학 / 연구방법론·통계 / AI 개발 / 인허가(RA)**. 사업 주제면 재무·법무·운영·시장 등으로 교체.

각 관점 패널: 태그 + 한 줄 소제목(핵심 명제) + 근거 3~4 bullet(그 분야 시니어의 용어와 기준) + `판정:` 한 문장.
네 패널 뒤에 수렴 다이어그램(4 노드 → 1 결론)과 수렴 문장(`.big`)으로 닫는다.

## 6. 표현 규칙 — 중립·정제 문어체

- 보고서 문어체("~하였다", "~로 확인되었다", "~라고 판단한다"). 구어·감탄·수사 의문 금지.
- 단정·감정 어휘 금지: 치명적, 실패, 폐기, 해지, 벽, 출구, 좌초 → 미충족, 진행이 어려움, 보류, 종료, 제약, 대안.
- 책임 귀속 표현 금지. "A가 못 해서" → "초기 전제와 이후 구체화된 요건 간의 차이".
- 상대 기관이 읽어도 불쾌하지 않을 문장만 쓴다. 상대의 기여를 먼저 인정한다.
- 확정되지 않은 사실은 "미확인", "확정되지 않음"으로 쓴다.
- 질의응답 답변은 사실 → 판단 순서, 끝은 "~라고 판단한다/제안한다".
- 제목은 주장형("~해야 하는 이유")이 아니라 중립형("~ 추진 방향 검토").

## 8. 완료 후 사용자에게 알릴 것

- 바뀐 점/설계 포인트 2~3개만 짧게
- 1차 자료를 확인하지 못해 비워둔 수치나, 톤 조정이 필요할 수 있는 민감 문장을 명시해 확인을 요청
