## 문서 추가 규칙

1. **파일명**: `YYMMDD_TB_<주제>_v<n>.html`. 수정은 새 버전으로. 회의록은 `YYMMDD_<주제>_회의록.html`.
2. **어디에 둘까**
   - 실명·협회 내부 판단·계약·IRB·인허가 내용이 없는 문서 → `01`·`02`
   - 인허가 문서 → `비공개_인허가문서/` 수정 후 관리자 메뉴 다시 생성 (아래)
   - 있는 문서 → `비공개_내부검토/` 또는 `비공개_원본자료/`
3. **문서함에 연결**: 새 문서는 반드시 `index.html` 메뉴에 한 줄 추가한다.
   ```html
   <a href="#짧은-id" data-src="02_회의록/261120_킥오프_회의록.html">📝 2026.11.20 킥오프</a>
   ```
   - 공개 문서 → 해당 번호 섹션에 바로 연결
   - 내부 문서 → `비공개_관리자메뉴.txt`에 추가 후 관리자 메뉴 다시 생성 (아래)
   - `#id`는 바꾸지 않는다. 외부에 공유된 링크(`.../Project_TB/#drf`)가 깨진다.
4. 공통 디자인을 입힘: `python 09_도구/sync_theme.py` (제목은 스크립트의 TITLES에 한 줄 추가)
5. 커밋·푸시하면 1~2분 뒤 GitHub 페이지에 반영됨.

## 관리자 메뉴 (비공개 문서 열람 · 문구 편집)

문서함 왼쪽 아래 **✏️ 편집 (관리자)** → 관리자 비밀번호 입력 → 「관리자 작업 공간」 메뉴(내부 검토 · 인허가 문서)가 나타남.
문서는 브라우저 안에서만 복호화되며, GitHub에는 암호문(`05_잠금문서/관리자/bundle.bin`)만 올라감. 메뉴 제목도 암호문 안에 있음.

**메뉴 갱신**
1. `비공개_관리자메뉴.txt`(git 제외)에 `그룹 | 제목 | 파일 경로` 줄을 추가·수정함. html·md는 화면에서 바로 열리고, xlsx 등은 내려받기로 제공됨.
2. 묶음을 다시 만듦 (비밀번호를 물어봄):
   ```bash
   python 09_도구/build_admin.py
   ```
3. `git add 05_잠금문서/관리자 && git commit -m "관리자 메뉴 갱신" && git push`

**공개 문서 문구 편집**: 로그인 후 「편집 토큰 설정」에서 GitHub 토큰(이 저장소만, Contents: Read and write)을 한 번 등록하면, 이후 공개 문서를 화면에서 고치고 저장하면 바로 커밋됨. 토큰은 관리자 비밀번호로 암호화되어 `05_잠금문서/관리자/token.json`에 보관됨. 관리자 문서는 PC 원본을 고친 뒤 위 2~3단계로 반영함.

예전 공유 링크(`#drf`, `#reg`, `#review` 등)는 관리자 로그인 후 해당 문서로 열림.

## 기밀 문서함 갱신

1. `비공개_기밀문서함/manifest.txt`에 `경로 | 제목 | 분류` 줄을 추가한다.
2. `python 09_도구/vault_build.py` (비밀번호를 물어본다)
3. 기밀 문서함 저장소에서 커밋·푸시한다.
   ```bash
   git -C 비공개_기밀문서함 add -A && git -C 비공개_기밀문서함 commit -m "vault 갱신" && git -C 비공개_기밀문서함 push
   ```

암호화는 PBKDF2-SHA256(600,000회) + AES-256-GCM. 비밀번호를 잃으면 복구할 수 없다. 보안서약서·교육 이수증 등 개인 서류는 기밀 문서함에도 올리지 않는다.
